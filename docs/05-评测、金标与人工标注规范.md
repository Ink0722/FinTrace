# FinTrace 评测、金标与人工标注规范

本文定义稳定的金标与人工判分规范；各模块待执行的评测清单、性能矩阵和历次运行结果统一维护在 [08-统一评测清单与实施记录.md](08-统一评测清单与实施记录.md)。

> 实现状态：当前已有问题集、批次回放、SQLite 运行轨迹和导出能力；正式指标计算器、人工/LLM 双评流程和专家盲评报告尚未统一落地。代码入口见 `evaluation/runner/`、`harness/tracing/`，实施状态统一登记在 `08-统一评测清单与实施记录.md`。

## 测试集与冻结规则

评测数据分为：原始多轮回放集、0.5M 长历史压力集、可恢复故障集、股权路径金标集、事件节点金标集和问题财报金标集。测试前冻结代码提交、Prompt、模型、工具、数据、索引、知识截止日和评测配置；调试集、开发集与最终测试集严格隔离。

原始 35 个 Session、1,410 个 Turn 用于自然回放，但不能单独证明 0.5M 能力。压力集需在不提示事实位置的条件下，以已标注的早期事实、长材料和干扰信息构造 50K、100K、200K、500K 累计历史，并测试实体、时间、指标和证据召回。

## 每轮金标与标注格式

当前 `questions_annotated_v1.jsonl` 使用精简平级结构，不设置嵌套 `annotation`，也不单独标注 `context_dependencies`、`gold_facts` 或 `forbidden_facts`：

```json
{
  "case_id": "SESSION-001-TURN-001",
  "session_id": "1",
  "turn_id": 1,
  "question": "今天市场上有哪些涨停的股票",
  "think_flag": false,
  "annotation_status": "completed",
  "answerability": "unanswerable",
  "required_entities": [],
  "required_date": null,
  "valid_tools": [],
  "required_chunk_ids": [],
  "chunk_version": null
}
```

| 字段 | 含义 |
| --- | --- |
| `case_id/session_id/turn_id/question` | 稳定样本标识、原始会话顺序和问题文本 |
| `think_flag` | 原数据附带的思考标记，仅作分层分析，不进入 Agent Prompt |
| `annotation_status` | `completed` 或 `review_required`；后者不得进入正式评分 |
| `answerability` | `answerable`、`unanswerable`、`clarification_required` |
| `required_entities` | 回答或执行所需的证券代码/主体；空数组表示不要求固定主体 |
| `required_date` | 问题所需的单一日期锚点；不再拆分 start/end 字段 |
| `valid_tools` | 可接受的 `tool.operation`；允许多个合理操作，不要求唯一执行序列 |
| `required_chunk_ids` | 文本问题可接受的冻结 Chunk；结构化工具问题可为空 |
| `chunk_version` | 使用 Chunk 金标时记录对应冻结版本 |

上下文不作为单独样本拆出来判分，也不额外标注依赖字段。Runner 必须按完整 Session 的 `turn_id` 顺序自然回放，由 Agent 自己决定继承或切换；评测再根据当前 Turn 的主体、日期、工具和答案表现判分。不得把后续 Turn 单独运行后据此评价多轮能力。

标注顺序为：按 Session 阅读上下文；判断可回答性；消歧主体；标准化日期；选择可接受工具；必要时选择 Chunk；完成自检。主体或必要条件不能唯一确定时标为 `clarification_required`，当前数据与工具不可能支持时标为 `unanswerable`，不能猜测补全。

## 正式指标与判分

| 类别 | 指标 | 单位 | 目标 |
| --- | --- | ---: | ---: |
| 完整 Agent | 回答准确率 | Turn | 90% |
| 完整 Agent | 关键事实 Recall | 金标事实 | 90% |
| 完整 Agent | 工具调用 Precision | 逻辑操作 | 92% |
| 完整 Agent | 自纠错成功率 | 可恢复故障 | 80% |
| 专项 | 股权路径端到端准确率 | 路径案例 | 85% |
| 专项 | 事件节点 Recall | 事件节点 | 85% |
| 专项 | 工具延迟达标率 | 有效工具调用 | 5 秒内 100% |
| 财务 | 风险预警 F1 | 公司-报告期-风险类型 | 85% |
| 财务 | 报告专家盲评优秀率 | 报告 | 80% |

回答准确率按预定义的事实、边界、状态和引用要求判定；关键事实 Recall = 正确召回金标核心事实数 / 金标核心事实数；工具 Precision = 必要且正确的逻辑操作数 / 实际逻辑操作数。工具重复重试、无关调用和越界操作计为错误。F1 需使用独立正负标签，规则命中率不可替代。

当前精简问题集本身不能自动计算回答准确率和关键事实 Recall：它没有逐 Turn 的 `gold_facts`。`required_chunk_ids` 只表示文本证据应召回到哪些冻结 Chunk，可用于证据召回检查，不能直接视为答案事实。正式评测时，回答准确率由人工与校准后的 LLM 裁判双评；关键事实 Recall 按竞赛口径由人工对照源数据和必要证据判定。若后续希望自动化这两项，应建立独立评分表或裁判结果表，不把复杂金标重新塞回原问题 JSONL。

### 财务风险金标

财务风险金标按“公司 + 目标报告期 + 风险类型”标注。标注者至少记录比较期间、知识截止日、`positive/negative/insufficient_data/not_applicable` 标签、严重度、必要财务证据、可选公告Chunk、判断理由和复核状态。风险类型使用冻结词表，不能临时用自然语言创建同义标签。

标注者必须直接检查财务数据与截止日前公告，不得查看系统 `risk_scan` 输出后照抄标签。`positive/negative` 进入Precision、Recall和F1；`insufficient_data/not_applicable` 分别计算识别准确率。异常信号不等于造假，不要求标注者作违法或欺诈认定。

阈值调整只允许使用开发集。最终测试集冻结后不得查看标签调参；行业字段尚未冻结时不得标注或宣称“行业异常”。同一案例由两名金融背景标注者独立标注，分歧由高年级标注者或专家仲裁。

## 判分分工与红线

程序判定 schema、实体/日期格式、操作合法性、数值容差、证据 ID、时间限制和可恢复故障结果；人工负责复杂语义、报告逻辑和边界表达；LLM 裁判只可在经校准的主观项中辅助，必须保存 Prompt、版本、样本和一致性结果。

下列错误触发该子项失败：无证据编造数字或来源；将主要股东快照说成完整控制链；把风险信号写为造假结论；使用截止日后材料；对不可回答问题虚构回答；遗漏必要澄清；将模型解释当作工具计算。

## 复核、仲裁与产物

标注采用试标、双人复核和仲裁流程。争议记录保留问题、候选标签、证据、裁决理由和版本。最终产物包括冻结金标、评测配置、逐 Turn 结果、工具与证据轨迹、错误分类、指标汇总、失败案例和环境信息。重复问题应报告稳定性；成本、P50/P95、人工一致率等作为诊断信息，不混入九项正式分数。
