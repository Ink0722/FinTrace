# FinTrace 数据资产与离线构建

离线数据构建与在线问答严格分离：原始数据只读，标准化数据可追溯，索引可重建，在线工具仅读取冻结产物。

## 代码审查索引

| 数据产品 | 构建入口 | 在线消费者 | 版本/血缘校验 |
| --- | --- | --- | --- |
| Document、Chunk、向量与 BM25 | `data_pipeline/documents/` | `tools/document_search/` | Chunk manifest、输入 SHA-256、Embedding/BM25 版本 |
| 财务指标 | `data_pipeline/financial/build_index.py` | `tools/financial_analysis/repository.py` | `financial-metrics-v1` 与 normalized 指纹 |
| 股东与主体关系 | `data_pipeline/entity_resolution/`、`data_pipeline/ownership/build_index.py` | `tools/ownership_analysis/repository.py` | `entity-master-v1`、`ownership-holdings-v3` |
| 公告事件 | `data_pipeline/events/build_index.py` | `tools/event_timeline/repository.py` | `announcement-events-v3.1` |
| 研报观点 | `data_pipeline/research_views/build_index.py` | `tools/research_analysis/repository.py` | `research-views-v1` 与冻结 Chunk 哈希 |

审查每个构建器时应确认：输入路径与哈希写入 manifest、完成文件采用原子替换、在线 Repository 在版本或指纹不一致时硬失败。具体统计数字应读取本地 manifest，不在本文硬编码为永久事实。

## 数据产品

| 数据产品 | 目标产物 | 面向能力 |
| --- | --- | --- |
| 会话与金标 | 回放集、标注集、压力集 | 多轮记忆与路由评测 |
| 股东快照 | 带时点和来源的持股边 | 股东查询、比较与路径计算 |
| 公告与事件 | 文档、事件记录和证据定位 | 检索、时间线与事件聚类 |
| 三张报表 | 标准指标长表与指标索引 | 查询、比较与风险规则 |
| 研报材料 | 元数据、摘要、结构化观点及原文定位 | 机构观点查询与原文检索 |
| 文本语料 | `Document`、冻结版 `Chunk` 与检索索引 | 文档证据检索 |

## 构建约束

- 每个产物记录输入路径、SHA-256、schema 版本、参数、记录数和生成时间。
- `chunks_v2` 是竞赛文本的冻结语料；索引不得静默重切分或改变 Chunk ID。
- 解析、清洗和下载失败必须被记录；不得用样例数据、伪向量或模型猜测替代生产数据。
- 数据切分、金标和最终测试集必须隔离，防止泄漏。

详细构建命令和产物契约以 `data_pipeline/README.md` 和相应构建脚本为准。

## 五类数据的标准化规则

### 多轮问题集

会话、Turn、用户问题、历史上下文、参考答案与标注分离存储。原始问答不是事实证据；当前标注文件以平级字段记录主体、日期、可回答性、可用工具与 Chunk 引用，真实字段以 `evaluation/questions/questions_annotated_v1.jsonl` 和 `05` 文档为准。会话顺序、原始文本和版本不可在清洗中改变。

### 十大股东快照

每行至少保留公司 ID、股东原名/规范名、股东 ID、快照日、披露日、持股数量、持股比例、排名、股份性质、来源文件/行及质量标记。快照是时点披露，不是完整股东名册；主体合并需保留别名与合并证据。有效快照按披露可见性和问题截止日选择，比较时必须说明两个时点。

### 违规公告与事件

公告元数据保留公告 ID、公司、标题、公告/事件日期、公告类型、URL/文件路径、页码与正文状态。事件记录保留事件 ID、主体、日期、类型、标题、描述、关联实体、来源文档与证据。标题级索引只支持标题级事实；事件分类、去重和聚类必须可回溯到原公告。

当前事件索引版本为 `announcement-events-v3.1`。离线构建额外抽取 `event_stage`、`date_precision`、监管机构、公告文号和主题签名；“不存在被处罚”等否定历史陈述不生成事件，并在manifest中单独计数。首版无法从标题获得事件实际发生日时，`event_date`使用公告日且标记为 `announcement_only`，不得对外表述为精确发生日期。

### 财务报表

三张表以长表统一：公司、报表类型、指标代码、原始科目名、数值、单位、币种、报告期、期间类型、披露日、来源和映射版本。指标目录维护原始科目到标准指标的多对一映射及适用报表。同比/环比仅在可比期间、单位、合并范围和累计口径一致时计算；不得将半年度累计与全年累计直接计算增长率。

### 研报材料与基础数据

研报保留报告 ID、股票代码、标题、机构、作者、发布日期、评级、评级变化、摘要、来源和质量标记。摘要可支撑“机构观点”，不可支撑全文细节。价格、市值、行业等基础数据需保留频率、复权口径、观察日、来源和适用范围，并与实时数据严格区分。

当前 `research-views-v1` 从研报元数据、标题和摘要固定栏目中确定性提炼 `investment_rating`、`earnings_forecast`、`risk_opinion`、`analyst_judgment` 和 `cited_fact`。正文栏目观点绑定 `chunk_id`；评级元数据和标题判断只保留文档级来源，禁止用模糊相似度伪造正文位置。索引写入 `data/indexes/research_analysis/research_views.sqlite`，manifest记录输入哈希、观点数、正文映射数和失败数。`cited_fact` 只表示研报引用了该事实，不代表系统已独立核验。

## 质量控制与血缘

每个标准化记录都应能回溯到原始文件、页/行、解析器版本和转换规则。质量检查包括必填字段、主键唯一性、日期可解析性、数值/百分比范围、跨表勾稽、实体别名冲突、快照重复、公告重复、缺失正文、异常单位与报告期可比性。问题闭环记录发现时间、影响范围、修复方式、复跑版本和验收结果。

原始数据不可覆盖；构建写入使用临时文件与原子替换；索引仅消费已通过校验的冻结数据。数据访问层以 Repository/DataSource 抽象隔离 CSV、SQLite 与图数据库实现，但它们必须遵守相同语义和返回协议。
