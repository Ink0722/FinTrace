# FinTrace 交付、部署、演示与答辩说明

## 交付范围

交付包含：可运行源代码、依赖与环境配置、离线数据构建脚本、版本化数据/索引 manifest、在线 API 或 Web 演示、评测 Harness 与冻结结果、技术白皮书和答辩材料。任何演示结果均需标明数据版本、知识截止日、模型版本和证据来源。

## 项目分层

`app/` 提供 CLI/API 入口；`harness/` 提供 Agent 编排、路由、证据、记忆与 Trace；`tools/` 提供独立可测的金融工具；`schemas/` 定义 Pydantic 契约；`data_pipeline/` 完成离线构建；`data/` 保存原始、标准化、处理和索引产物；`prompts/` 保存运行时 Prompt；`tests/` 支撑回归，`runtime/fintrace.sqlite3` 统一保存会话记忆、用户归属、评测与调试运行记录。

## 运行与部署原则

- 使用 `.env.example` 作为配置模板，密钥仅置于本地环境变量或密钥管理系统，不写入文档、Trace 或数据集。
- CLI 与 API 调用同一 Agent 入口；工具必须可脱离 Agent 单独测试。
- 没有真实数据或索引时，演示必须显式显示数据状态，不能将样例结果伪装为竞赛结果。
- 任何部署包附带依赖锁定、启动命令、健康检查、日志位置、数据版本和回滚说明。

## 演示脚本

演示至少覆盖：多轮实体/日期继承；带引用的公告或研报检索；同口径财务查询与比较；主要股东快照和变动；事件时间线；证据不足、输入歧义与能力不支持的诚实处理；Trace 与证据定位展示。目标能力尚未通过金标验证时，演示应称为“目标流程”或“开发演示”，不得称为达标结果。

## 答辩结构

1. 赛题痛点与三项任务；2. 数据资产和证据边界；3. Agent Harness 与防幻觉机制；4. 图谱、事件和财务勾稽方法；5. 评测设计及冻结结果；6. 演示；7. 局限、合规与后续计划。

强调“程序计算 + 可追溯证据 + 有界 LLM 决策”，并用已冻结指标而非架构名词证明效果。不得把历史价格说成实时行情、把主要股东说成完整控制链，或把风险提示说成财务造假认定。
