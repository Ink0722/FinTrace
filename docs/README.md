# FinTrace 文档导航

本目录的文档按权威性和用途分层，避免将竞赛目标、当前实现和历史方案混作同一口径。代码审查应先看根目录 `README.md` 的审查顺序，再按本页进入专题文档。

## 文档类型

| 类型 | 文档 | 审查用途 |
| --- | --- | --- |
| 外部约束 | `00` | 说明必须达到什么，不证明当前已经达到。 |
| 目标契约 | `01`、`05`、`06` | 说明能力、评测和交付应满足的边界。 |
| 数据实现 | `02`、`03` | 对照 `data_pipeline/`、`data/README.md` 和索引 manifest。 |
| 在线实现 | `04` | 对照 `harness/`、`schemas/`、`app/` 和工作流测试。 |
| 专项实现 | `07` | 对照风险、事件和股权穿透源码及专项测试。 |
| 评测方法 | `09` | 定义指标、判分边界、金标表和白皮书结果模板。 |
| 评测台账 | `08` | 登记待办、批次、诊断结果和失败案例。 |

## 阅读顺序

1. [竞赛要求与验收口径](00-竞赛要求与验收口径.md)：赛题目标、验收指标和交付物。
2. [系统目标能力与数据边界](01-系统目标能力与数据边界.md)：系统应提供的能力及其证据边界。
3. [数据资产与离线构建](02-数据资产与离线构建.md)：数据产品、血缘和构建约束。
4. [文本语料、Document、Chunk 与检索索引](03-文本语料、Document、Chunk与检索索引.md)：文本证据的构建、冻结和检索。
5. [在线 Agent、记忆、路由与证据工作流](04-在线Agent、记忆、路由与证据工作流.md)：目标工作流与 Prompt 治理。
6. [评测、金标与人工标注规范](05-评测、金标与人工标注规范.md)：回放、标注、指标、仲裁与复现。
7. [交付、部署、演示与答辩说明](06-交付、部署、演示与答辩说明.md)：交付边界与演示口径。
8. [风险扫描、事件脉络与股权穿透实现审查](07-风险扫描、事件脉络与股权穿透开发计划.md)：三个专项能力的代码映射、边界和测试入口。
9. [统一评测清单与实施记录](08-统一评测清单与实施记录.md)：评测对象、指标、数据集、待办与已运行结果。
10. [Agent评测实施方案与结果模板](09-Agent评测实施方案与结果模板.md)：九项竞赛指标的计算口径、人工表格、质控流程与白皮书模板。

## 权威来源

| 内容 | 唯一依据 |
| --- | --- |
| 竞赛任务、数据范围、验收阈值与交付物 | `archive/competition-source/参赛要求编辑版.docx` |
| 运行时真实行为、已实现操作和状态字段 | 源代码与测试 |
| 离线构建命令、产物和版本冻结 | `data_pipeline/` 的脚本与 README |
| Prompt 正文、版本和装配规则 | `prompts/` |

`00`、`01`、`05`、`06` 以目标和验收口径为主；`09` 是正式评测方法；`02`、`03`、`04`、`07`、`08` 可以记录当前实现，但必须给出源码、测试或 manifest 锚点。任何没有冻结数据集和可复现报告的数字，只能标记为诊断结果，不能写成竞赛指标已达标。

- 章节级迁移关系见 [文档迁移台账](MIGRATION.md)。
