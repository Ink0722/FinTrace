## 1. 评测原则

- 分开评测完整 Agent、单项工具和回答报告，不用最终答案掩盖工具错误。
- 每项指标必须明确样本单位、分子、分母、通过阈值和不纳入条件。
- 固定代码提交、Prompt版本、模型配置、数据manifest、索引版本和 `knowledge_cutoff`。
- 工具延迟只计算工具入口到 `ToolResult` 返回，不包含LLM解析和答案生成。
- 空结果、数据不足和正确拒答是有效行为，不强迫系统生成结论。
- P50、P95、最大值、错误类型分布属于诊断项，不随意增加为竞赛正式指标。

## 3. 事件工具专项评测

### 3.1 数据集与标注

从冻结公告数据中分层抽取公司和时间窗，覆盖监管问询、监管处罚、审计意见、控制权变更、质押、财务更正、重大诉讼和风险警示。标注单位为“公司 + 时间范围”，每个案例至少记录：

```json
{
  "case_id": "EVENT-001",
  "company_id": "000001.SZ",
  "start_date": "2022-01-01",
  "end_date": "2024-12-31",
  "knowledge_cutoff": "2024-12-31",
  "gold_event_ids": ["EVT-..."],
  "gold_clusters": [["EVT-...", "EVT-..."]],
  "gold_stages": {"EVT-...": "initial"},
  "notes": "只标公告能够支持的事实"
}
```

事件节点金标必须能回溯到公告。否定历史陈述（例如“最近五年不存在被处罚”）不标为已发生事件。正文无法证明时，不标处罚金额、实际发生日期或因果关系。

### 3.2 指标

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 事件类型准确率 | 类型正确事件数 / 被评事件数 | 检查规则分类 |
| 事件节点Recall | 命中金标节点数 / 金标节点总数 | 对应竞赛>=85% |
| 否定陈述误建率 | 被误建为事件的否定公告数 / 否定公告数 | 防止虚假事件 |
| 阶段准确率 | 阶段正确节点数 / 有阶段金标节点数 | 检查initial/progress/response等 |
| 聚类Precision | 正确同簇事件对 / 系统同簇事件对 | 检查错误合并 |
| 聚类Recall | 被正确合并的金标事件对 / 金标同簇事件对 | 检查漏合并 |
| 时序正确率 | 日期非递减且无未来信息的案例数 / 案例数 | 检查排序和截止日 |
| 证据可追溯率 | 可定位源公告的事件数 / 返回事件数 | 目标100% |

聚类F1仅作为工具诊断指标，不替代竞赛要求的关键事件节点Recall。“关系正确率”只评估带明确共享文号的关系；工具没有生成关系时不因缺少推测性因果链扣分。

### 3.3 性能矩阵

分别测试单类型/多类型、有结果/无结果、1年/5年/全周期、带/不带 `knowledge_cutoff`、`event_query`/`event_cluster`。每类至少运行30次，预热后记录P50、P95、最大耗时和错误率。正式延迟口径为工具内部 `execution_time_ms`。

## 4. 研报观点专项评测

研报工具的评测单位是“结构化观点”，不是最终回答。按机构、年份和观点类型分层抽取样本，由标注者对照研报元数据与摘要，记录 `report_id`、`company_id`、`institution`、`publish_date`、`claim_type`、`claim_text` 和可用时的 `chunk_id`。不要求标注研报未提供的客观真值。

| 指标 | 定义 | 目标或用途 |
| --- | --- | --- |
| 观点类型准确率 | 类型正确的观点数 / 被评观点数 | 检查评级、预测、风险等分类 |
| 观点归属准确率 | 公司、机构、日期均正确的观点数 / 被评观点数 | 防止串公司或串机构 |
| 正文可追溯率 | 可定位正确Chunk的正文型观点数 / 正文型观点数 | 目标100% |
| 观点文本忠实率 | 未增加原文没有的数值、方向或因果的观点数 / 被评观点数 | 防止抽取扩写 |
| 事实升级错误率 | 被错误表述为已核实公司事实的研报观点数 / 返回观点数 | 目标0% |
| 截止日正确率 | 未返回 `knowledge_cutoff` 后研报的案例数 / 截止日案例数 | 目标100% |

标题和评级元数据属于文档级来源，不纳入“正文可追溯率”的分母；这不是缺失Chunk。研报中的 `cited_fact` 只标为“研报引用事实”，不评为系统已独立核实。对“为什么这样判断”的调查案例，另检查是否先调用 `research_analysis`，再按需调用限定 `research_report` 的 `document_search`。

## 5. 财务风险专项评测

金标单位为“公司 + 目标报告期 + 风险类型”。标注者使用冻结财务记录和截止日前可见的公告证据独立判断，不以系统规则输出作为金标来源。开发集用于阈值调整，最终测试集只运行一次并与开发人员隔离。

```json
{
  "case_id": "RISK-001",
  "company_id": "000001.SZ",
  "report_period": "2024-12-31",
  "comparison_periods": ["2022-12-31", "2023-12-31", "2024-12-31"],
  "knowledge_cutoff": "2025-04-30",
  "risk_type": "inventory_revenue_divergence",
  "label": "positive",
  "severity": "medium",
  "required_metric_evidence_ids": ["EVID-..."],
  "supporting_chunk_ids": ["ANN-...-C0001"],
  "rationale": "存货增速连续高于收入增速，且差额超过标注阈值。",
  "review_status": "adjudicated"
}
```

`label` 只使用 `positive`、`negative`、`insufficient_data`、`not_applicable`。正负样本都必须标注；输入不足和规则不适用不进入风险F1的正负分母，而是分别计算识别准确率。标注者判断的是可观察风险信号，不直接标注“公司造假”。

| 指标 | 定义 | 用途 |
| --- | --- | --- |
| 风险Precision | 正确正向预警 / 全部正向预警 | 控制误报 |
| 风险Recall | 正确正向预警 / 全部金标正样本 | 控制漏报 |
| 风险F1 | Precision与Recall调和平均 | 对应竞赛>=85% |
| 数据不足识别准确率 | 正确识别输入不足案例 / 金标输入不足案例 | 防止缺数据被写成低风险 |
| 不适用识别准确率 | 正确识别口径不适用案例 / 金标不适用案例 | 检查负值、零值等边界 |
| 逐期间定位准确率 | 正确定位异常期间段 / 金标异常期间段 | 检查首尾比较遗漏 |
| 期间解析准确率 | 实际计算期间符合目标期间和确定性选择规则的案例 / 期间案例 | 检查单目标扩展、未指定默认和截止日 |
| 证据可追溯率 | 输入证据完整的信号 / 返回信号 | 目标100% |

阈值校准只在开发集执行，记录候选阈值、Precision/Recall变化和选择理由。当前 `financial-risk-rules-v2` 标记为 `uncalibrated`，不得把真实冒烟结果宣称为F1达标结果。

## 7. 执行与产物

建议统一目录：

```text
evaluation/
  questions/      冻结问题集与标注
  runner/         批次准备、回放和状态管理
  exports/        按需生成的JSONL评测交换文件
runtime/
  fintrace.sqlite3  会话、运行轨迹和评测批次唯一事实源
```

每次正式运行报告至少记录：运行ID、Git提交、Prompt版本、模型、数据manifest哈希、索引mapping version、样本数、指标结果、P50/P95/最大延迟、失败类型和已知限制。
