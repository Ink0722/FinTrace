# FinTrace 研报摘要数据设计与 Agent 应用方案

## 1. 文档目的

本文档定义比赛数据组 5 公司研报元数据和摘要的存储、检索、结构化分析、证据表达及 Agent 接入方案。

该数据同时包含两类信息：一类是机构、作者、评级、行业和日期等结构化元数据；另一类是研报摘要文本。结构化筛选应由 SQLite 完成，语义检索由 BM25 和 FAISS 完成，大模型负责在检索结果范围内归纳机构观点。

研报属于机构观点，不等同于财务事实、公司公告或已经实现的预测结果。

### 1.1 对应竞赛任务与指标

研报摘要是任务 2 事件解释和任务 3 财务归因的辅助证据源，不单独承担股权穿透或财务欺诈判断。它主要帮助 Agent 检索机构如何解释某项事件、经营变化和风险因素。

在事件时间线评测中，研报观点只有在明确描述事件且绑定机构、日期和摘要证据时才能作为补充节点；在财务报告中，它只能解释结构化指标，不能改变确定性计算或充当欺诈标签。

当前只有摘要而无全文，因而不应把它计入“全文无损长文本读取”或逐页引用能力。若后续取得合法研报全文，可作为 0.5M 长上下文检索和复杂观点查证的补充语料。

## 3. 字段解释

| 原始字段 | 含义 | 系统用途 |
|---|---|---|
| `id` | 来源记录 ID | 数据审计辅助 ID |
| `report_id` | 研报 ID | 稳定 `document_id` 和主键 |
| `org_name` | 研究机构名称 | 机构过滤和观点归属 |
| `org_id` | 机构 ID | 机构稳定标识 |
| `author` | 作者 | 作者过滤和展示，需拆分多人列表 |
| `title` | 标题 | 关键词检索和结果展示 |
| `write_date` | 撰写日期 | 观点形成时间 |
| `publish_date` | 发布日期 | 对外可知时间和默认排序依据 |
| `sec_code` | 证券代码主体 | 与 `exchange_code` 组合成标准证券代码 |
| `sec_name` | 证券名称 | 名称检索和证券主表校验 |
| `report_type` | 研报类型 | 当前全部为公司研究 |
| `report_sub_type` | 研报细分类型 | 业绩点评、事件点评、公司深度等过滤 |
| `exchange_code` | 交易市场代码 | 映射 `.SH`、`.SZ`、`.BJ` 等后缀 |
| `tar_price` | 目标价 | 结构化观点字段，缺失较多 |
| `tar_price_val` | 目标价有效期 | 目标价口径辅助字段，几乎全部缺失 |
| `tar_price_max` | 目标价上限 | 区间目标价辅助字段，几乎全部缺失 |
| `rating_org` | 原始评级文本 | 展示机构原始评级 |
| `rating_id` | 评级 ID | 来源侧评级标识 |
| `rating_change` | 评级变动 | 维持、上调、下调等结构化过滤 |
| `first_cover` | 是否首次覆盖 | 首次覆盖查询 |
| `industry_l1/l2/l3` | 行业分类 | 行业筛选和聚合 |
| `sw_indu_code` | 申万行业代码 | 稳定行业映射 |
| `abstract` | 研报摘要 | 文本检索和机构观点证据 |
| `page_count` | 原研报页数 | 元数据，不是摘要所在页码 |
| `is_weekly` | 是否周报 | 当前几乎全部为非周报 |
| `file_size` | 原文件大小 | 来源元数据 |
| `tmstamp` | 来源时间戳 | 数据审计字段 |

原始数据没有研报 PDF 链接或本地正文路径。`page_count` 只说明原研报页数，不能据此为摘要生成页码引用。

## 4. 数据质量与口径

### 4.1 主要缺失情况

| 字段 | 缺失率 |
|---|---:|
| `tar_price` | 80.04% |
| `tar_price_val` | 98.22% |
| `tar_price_max` | 99.45% |
| `rating_change` | 12.47% |
| `rating_org` | 2.23% |
| `rating_id` | 2.24% |
| 行业字段 | 约 0.67% |
| `report_sub_type` | 0.89% |

摘要和证券代码具有较高可用性。目标价不适合作为第一版主要能力；查询目标价时必须明确缺失情况，不能从摘要中猜测。

### 4.2 评级变化字段

`rating_change` 的原始值包括：

```text
维持、上调、下调、调高、调升、调低
```

标准化时可以映射到：

```text
maintained
upgraded
downgraded
unknown
```

但必须同时保留原始值。评级名称本身也存在“买入”“买入-A”“强烈推荐”“优于大市”等机构差异，不能未经机构评级体系映射就直接横向排序。

### 4.3 日期选择

- `write_date` 表示研报中披露的撰写日期；
- `publish_date` 表示对外发布日期；
- 历史可知性查询使用 `publish_date`；
- 展示时可以同时给出两个日期。

回答“截至某日市场已发布的研报”时，必须要求 `publish_date <= as_of_date`。

### 4.4 证券代码标准化

`sec_code` 需要结合 `exchange_code` 转换为标准代码。常见映射至少包括：

```text
XSHG -> .SH
XSHE -> .SZ
XBEI -> .BJ
```

数据中还出现少量境外或其他市场代码。未知交易所不得默认拼成 `.SZ`，应保留原代码并标记 `unsupported_exchange`，直到证券主表确认。

## 5. 本数据可以实现的功能

### 5.1 最新研报查询

- 某公司近期有哪些研报；
- 某机构近期覆盖了哪些公司；
- 某公司最新的业绩点评或事件点评；
- 某公司是否出现首次覆盖报告。

“最新”指数据集范围内按 `publish_date` 排序的最新记录，不代表当前互联网的最新研报。

### 5.2 研报语义检索

- 检索机构如何解释收入、利润、现金流或库存变化；
- 查找研报中的风险提示；
- 检索某一业务、产品、政策或事件的相关观点；
- 找到支持或质疑某个投资逻辑的摘要片段。

### 5.3 评级变化

- 某公司近期有哪些评级上调或下调；
- 某机构是否维持评级；
- 首次覆盖时给出了什么评级；
- 某段时间内评级变化记录。

评级变化应按机构分别展示。不同机构评级体系不同，不能把所有评级文字简单映射成统一分数后宣称“市场一致评级”。

### 5.4 多机构观点比较

可以基于多篇摘要总结：

- 机构共同关注的增长驱动；
- 机构共同提示的风险；
- 对盈利、产能、现金流或行业景气的观点差异；
- 评级和预测方向的差异。

答案必须标明观点所属机构和研报日期，避免把多篇研报融合成无来源的统一结论。

### 5.5 行业维度检索

行业字段可用于过滤公司研报，例如：

- 某申万一级行业近期公司研报关注哪些主题；
- 某行业下哪些公司被频繁覆盖；
- 某行业公司研报中的共同风险提示。

这仍然是“属于该行业的公司研究摘要集合”，不是完整行业研究报告集合。

## 6. 本数据不能单独支持的结论

该数据不能单独支持：

- 研报全文逐页引用；
- 摘要未包含的模型假设和详细预测表；
- 当前实时的最新研报；
- 完整行业研报覆盖；
- 所有机构的一致预期；
- 目标价的完整统计；
- 评级对应的确定收益；
- 研报观点已经被事实验证；
- 机构观点导致股价变化的因果结论。

Agent 不得把“预计”“有望”“我们认为”等研报表述改写成已经发生的事实。

## 7. 双层存储设计

### 7.1 结构化元数据表

建议在 `data/structured/fintrace.sqlite` 建立：

```text
research_reports
- report_id
- source_record_id
- company_id
- sec_code_raw
- sec_name
- exchange_code
- org_id
- org_name
- title
- write_date
- publish_date
- report_type
- report_sub_type
- rating_raw
- rating_id
- rating_change_raw
- rating_change_normalized
- first_cover
- industry_l1
- industry_l2
- industry_l3
- sw_indu_code
- target_price
- target_price_max
- target_price_validity
- abstract
- page_count
- source_file
- quality_flags
- evidence_id
```

作者建议拆分为关联表：

```text
research_report_authors
- report_id
- author_name
- author_order
```

### 7.2 文档知识库

研报摘要同时进入现有文档知识库：

```text
document_id = RR-<report_id>
document_type = research_report
company_id = 标准证券代码
title = 研报标题
published_date = publish_date
source_file = 原始 CSV + 稳定行标识
```

摘要长度中位数约 1,110 字符。推荐：

- 短摘要保留为一个 Chunk；
- 长摘要按语义段落切分；
- Chunk 目标长度约 700～1,000 个中文字符；
- 重叠控制在 80～120 字符；
- 不按固定字符粗暴切断数字、公司名称和完整句子；
- 每个 Chunk 继承机构、评级、行业和发布日期元数据。

原始 CSV 不是 PDF，Chunk 的 `page` 必须为空。

## 8. 检索设计

### 8.1 先过滤后检索

推荐流程：

```text
结构化过滤
  company_id / org_id / report_sub_type / industry / date
    -> 候选研报
      -> BM25 + FAISS 混合检索
        -> 去重与多样性重排
          -> 返回 Top-K 摘要片段
```

不能先在 55,214 篇全部摘要中语义搜索，再希望大模型自行识别公司和日期。

### 8.2 混合检索

- BM25 适合证券名称、机构名称、具体指标和专有名词；
- FAISS 适合“利润承压原因”“海外拓展风险”等语义表达；
- Hybrid 合并两种召回结果；
- 最终分数不应被回答模型解释为投资评级或置信概率。

### 8.3 多样性控制

当用户问“多家机构怎么看”时，简单 Top-K 可能全部来自同一家机构。应支持：

```text
max_hits_per_report = 1
max_reports_per_org = 可配置
diversify_by = org_name
```

当用户明确查询某一家机构时，则不进行跨机构多样性限制。

### 8.4 最新与相关性的平衡

“最新研报”按发布日期排序；“关于某风险的研报”按相关性排序，并可加入温和的时间衰减。不能在没有说明的情况下让新但不相关的研报压过高度相关旧研报。

## 9. 接入 `document_search`

### 9.1 查询参数

```json
{
  "query": "经营现金流下降的原因",
  "company_id": "002563.SZ",
  "document_types": ["research_report"],
  "start_date": "2025-01-01",
  "end_date": "2026-05-28",
  "organizations": [],
  "report_sub_types": ["业绩点评"],
  "rating_changes": [],
  "top_k": 8,
  "mode": "hybrid",
  "diversify_by": "org_name"
}
```

现有 `document_search` 已支持公司、文档类型、日期和混合检索。正式接入还需把机构、研报子类型、行业和评级等元数据加入知识库 Schema 和过滤条件。

### 9.2 结构化查询与文本检索分工

| 问题 | 处理方式 |
|---|---|
| “最新三篇研报是什么？” | SQLite 按 `publish_date` 排序 |
| “哪些评级被下调？” | SQLite 过滤标准化评级变化 |
| “机构为何下调评级？” | 先结构化定位，再检索摘要文本 |
| “多家机构怎么看现金流？” | 按公司过滤，混合检索并按机构多样化 |

不应把所有请求都转换为向量搜索。

## 10. 是否需要新增工具

第一版继续使用 `document_search`，不新增 Agent 可见工具。结构化研报查询可以作为 `document_search` 内部的检索策略。

当以下需求稳定出现时，再考虑新增 `research_analysis`：

- 评级时间序列；
- 多机构一致预期；
- 盈利预测标准化；
- 机构观点聚类；
- 行业级研报统计。

新增工具的条件是它需要独立的确定性聚合逻辑，而不是单纯为了换一个名字。

## 11. 与 `financial_risk_analysis` 联合使用

财务工具提供事实和指标，研报提供解释性观点：

```text
financial_risk_analysis
  -> 2024 年经营现金流同比下降

document_search(research_report)
  -> 某机构认为下降与库存、付款节奏或业务扩张有关
```

最终回答应分开陈述：

```text
财务数据表明……
机构 A 在某日研报中认为……
```

研报观点不能用于改变财务规则的确定性计算结果，也不能作为财务数字的唯一来源。

## 12. 证据设计

研报元数据证据：

```text
EVID-RR-<report_id>-META
```

摘要 Chunk 证据：

```text
EVID-RR-<report_id>-CHUNK-<chunk_index>
```

证据类型使用 `institution_opinion` 或 `document_excerpt`，并至少包含：

```json
{
  "report_id": "5971493",
  "company_id": "601033.SH",
  "org_name": "东吴证券",
  "authors": ["袁理", "陈孜文"],
  "title": "...",
  "publish_date": "2025-04-01",
  "rating_raw": "买入",
  "rating_change": "maintained",
  "report_sub_type": "业绩点评",
  "text": "摘要片段",
  "content_level": "abstract"
}
```

`content_level=abstract` 必须传给回答模型，防止其声称内容来自研报全文。

## 13. Agent 工作流

```text
用户问题
  -> Planner 识别研报、评级、机构观点或行业主题
  -> 解析公司、机构、时间、研报类型和主题
  -> document_search 先做结构化过滤
  -> 必要时执行 BM25 + FAISS
  -> 对结果做报告级去重和机构多样化
  -> Evidence Guard 检查观点归属和 content_level
  -> Answer Generator 按机构和日期归纳观点
```

典型处理：

| 问题 | 处理方式 |
|---|---|
| “某公司最新研报有哪些？” | 按公司和日期结构化查询 |
| “某机构为什么维持买入？” | 机构、公司和评级过滤后检索摘要 |
| “多家机构怎么看库存风险？” | 公司过滤、语义检索、机构多样化 |
| “研报全文第几页提到该风险？” | 当前数据不支持，应明确只有摘要 |

## 14. 回答生成约束

回答模型必须：

- 明确观点所属机构和发布日期；
- 使用“认为”“预计”“研报指出”等观点性表达；
- 区分研报摘要与全文；
- 不把预测写成已经发生的事实；
- 不把评级解释为收益保证；
- 不在目标价缺失时推断目标价；
- 不把不同机构观点混成无来源结论；
- 不引用不存在的页码；
- 对数据截止日期作出说明。

---

## 15. 与当前代码的适配缺口

现有知识库支持文档 Chunk、BM25、FAISS 和混合检索。接入研报数据还需：

1. CSV 研报导入器；
2. 交易所代码与证券主表映射；
3. `research_reports` 和作者关联表；
4. 将摘要直接写入知识库的结构化入口；
5. 机构、子类型、行业和评级元数据 Schema；
6. 结构化排序与过滤；
7. 报告级去重和机构多样化；
8. `institution_opinion` 和 `content_level=abstract` 证据；
9. 评级变化标准化；
10. 检索质量和观点归属测试。

现有文件型知识库构建器只支持 TXT、MD、DOCX 和 PDF。研报 CSV 不应先批量生成临时 TXT，而应新增结构化研报导入路径，直接写入 `documents`、`chunks` 和研报元数据表。

## 16. 推荐实施顺序

1. 建立证券代码和交易所映射；
2. 导入 `research_reports` 和作者表；
3. 实现最新研报、机构和评级结构化查询；
4. 将摘要切分并写入知识库；
5. 构建 BM25 和 FAISS 检索；
6. 加入研报元数据过滤；
7. 实现报告去重和机构多样化；
8. 加入观点证据和回答约束；
9. 与财务工具联合测试；
10. 根据需求决定是否新增 `research_analysis`。

第一版应先完成“最新研报查询”和“单公司摘要检索”，再实现多机构综合。前两项结果容易验证，也是多轮问题集中直接出现的能力。

---

## 17. 最终原则

这组数据应被建设为“可过滤、可检索、可归属的机构观点库”。SQLite 负责精确元数据，BM25 和 FAISS 负责摘要召回，大模型负责有限归纳。

FinTrace 必须始终回答清楚：这是哪家机构在什么时候提出的观点、依据的是摘要还是全文，以及该观点是否属于预测。只有这样，研报才能成为可靠的解释性证据，而不是另一种形式的模型幻觉。
