# FinTrace 在线 Agent 与证据工作流

## 目标工作流

```text
请求与必要上下文
  -> 请求解析（实体、时间、任务）
  -> 可回答性判断
  -> 简单请求的确定性直达 / 复杂请求的有界调查
  -> 动作校验
  -> 单次工具执行与结果校验
  -> 证据合并与充分性审查
  -> 基于证据的回答、部分回答、澄清或拒答
  -> 会话与审计记录
```

## 设计原则

- LLM 决定下一项值得调查的动作；程序完成计算、检索、过滤、图遍历和边界校验。
- 每次调查只执行一个已校验动作；重试和修复必须受预算、次数和原因约束。
- 最终回答只能引用证据账本中的已验证事实；证据缺口应显式呈现。
- 会话记忆分为近期原文、结构化上下文、滚动摘要与已验证事实；未验证推测不得进入长期记忆。
- Trace 记录输入版本、动作、工具结果、证据、终止原因和模型调用元数据，不记录不可验证的私有推理链。

详细工程节点和状态字段见 `13-Agent决策与证据驱动调查技术白皮书.md`；其中的目标能力必须同本目录的边界约束一起阅读。
